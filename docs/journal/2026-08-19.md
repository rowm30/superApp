## 5. What is built and working

### Auth / identity
- Keycloak realm `superapp` fully **as code** in `infra/local/keycloak/superapp-realm.json`
  (auto-imported via `start-dev --import-realm`). Contains realm role `seller`,
  clients `web-shell` (public, auth-code + PKCE S256, no password grant) and
  `local-test-cli` (password grant, **local testing only**), user `mayank.test`/`test123`,
  and an `oidc-audience-mapper` on each client injecting audience `profile-api`.
- Walked a full **authorization-code + PKCE flow by hand** (openssl verifier/challenge,
  browser auth endpoint, curl token exchange) before using any library.
- **edge-gateway** validates the JWT (`issuer-uri` → JWKS), then mints internal
  `X-Passport-Sub` / `-Sid` / `-Username` headers via a `GlobalFilter`
  (`PassportFilter`). It **strips** any client-supplied passport headers —
  `.header()` replaces rather than adds. Verified with a spoofing test.
- Downstream services read **only** the passport. `profile-service` and
  `product-service` have **zero** security dependencies and no Keycloak config.
- Angular login works end-to-end (`angular-oauth2-oidc`, `provideOAuthClient()`,
  signals for reactivity since Angular 21+ is zoneless).
- CORS configured on the gateway path; verified that a CORS block shows as
  HTTP status **0** (browser-blocked, never reaches the server).

### Product service (8083)
- Flyway: `V1` products table, `V2` stock column + non-negative CHECK,
  `V3` `processed_events` table.
- `Product` entity, `ProductRepository`, create + list-mine + list-all + get-by-id.
- **Mass-assignment guard**: `CreateProductRequest` record has no `sellerId`;
  it always comes from the passport. Verified with a spoofing test.
- Kafka **consumer** of `order.placed.v1` with idempotency via
  `INSERT ... ON CONFLICT DO NOTHING` on `processed_events`, and an
  **atomic** `UPDATE ... SET stock = stock - :qty WHERE stock >= :qty`
  (avoids lost-update race).

### Order service (8084)
- Flyway `V1`: `orders` + `order_items` with FK + `CHECK (quantity > 0)`.
- `Order` / `OrderItem` / `OrderStatus` entities. `@OneToMany` with `mappedBy`,
  cascade ALL, orphanRemoval, and an `addItem()` helper that sets both sides.
- **Price snapshot**: order_items copies `product_name` and `unit_price` at
  purchase time. `product_id` is a plain BIGINT, **not** an FK (different database).
- `OrderService.placeOrder()` calls product-service over REST (`RestClient.create()`),
  **forwarding the passport headers** (identity propagation).
- `GlobalExceptionHandler` returns RFC 9457 `ProblemDetail` with three distinct
  outcomes: **400** product doesn't exist, **503** product-service unreachable,
  **502** product-service errored. Never leaks `ex.getMessage()`.
- Kafka **producer** → `order.placed.v1`, key = orderId (partition ordering),
  `acks=all`.

## 6. Key decisions and rationale

| Decision | Why |
|---|---|
| Passport at gateway, not tokens downstream | Netflix edge-auth pattern; makes the IdP swappable (Keycloak → Cognito touches only the gateway) |
| Cognito in prod, not a hand-built IdP | Supersedes ADR-0001's "BUILD P1" — scope/risk reduction |
| WebFlux gateway, WebMVC services | His call: expects reactive demand to grow. Mixing is fine |
| REST not gRPC for order→product | Low call volume; debuggability outweighed perf. "REST at edge, gRPC inside" is the pattern to adopt when volume justifies it |
| DB per service | Prevents distributed monolith; forces the snapshot design |
| Flyway, `ddl-auto=none` | Schema in version control; survived a full Docker wipe |
| Roles NOT in the passport | ADR-0001: passport is identity, not permissions (avoids stale-cache) |

## 7. Known gaps / deliberate shortcuts

1. **Dual-write problem** — event publish is inside `@Transactional`. Kafka down
   → the whole order fails (observed live). Fix is the **outbox pattern**.
2. **R2 from ADR-0001** — services are reachable directly (e.g. `curl :8081/me`
   with a forged header works). Only safe because it's local. Needs network
   isolation / mTLS before any deploy.
3. **Roles not in the passport** — so `@PreAuthorize` was removed from
   product-service when it moved to passport-only. No RBAC downstream yet.
4. `createdAt` returns `null` on POST responses (DB `DEFAULT now()` isn't read
   back by Hibernate). Cosmetic.
5. No pagination on `GET /products`.
6. **No tests at all.** No CI. Not deployed.
7. `local-test-cli` uses the password grant, which OAuth 2.1 removes. Test-only,
   isolated to its own client.

## 8. Environment gotchas (all hit at least once)

- **Spring Boot 4 modularization**: raw libraries no longer bring
  autoconfiguration. Always use the starter — `spring-boot-starter-flyway`,
  `spring-boot-starter-kafka`, `spring-boot-restclient`. Hit this 3 times.
- **Jackson 3**: Boot 4 uses `tools.jackson.*`. Spring Kafka's `JsonSerializer` /
  `JsonDeserializer` are deprecated — use **`JacksonJsonSerializer`** /
  **`JacksonJsonDeserializer`**.
- **Kafka type headers**: set `spring.json.add.type.headers=false` on the producer
  and `spring.json.use.type.headers=false` on the consumer, or the consumer needs
  the producer's exact package. Set these **before** publishing any events.
- **Poison pill**: use `ErrorHandlingDeserializer` wrapping the real deserializer,
  and null-check in the listener. Without it one bad message loops forever.
- **Gateway config must be YAML**, not `.properties` — relaxed binding lowercases
  `Path=` and breaks the predicate. Also: **no spaces around `=`** in predicates.
- **Git Bash**: `export MSYS_NO_PATHCONV=1` before any `docker exec` with an
  absolute container path, or paths get rewritten to `C:/Program Files/Git/...`.
- **Windows CRLF**: `openssl base64` emits `\r`; strip with `tr -d '\n\r='`.
  `cat -A` shows `^M`.
- Keycloak 26.x uses `KC_BOOTSTRAP_ADMIN_USERNAME`, not `KEYCLOAK_ADMIN`.
- Don't put a top-level `clientScopes` array in a realm import JSON — it replaces
  the built-in scopes and silently drops `realm_access` from tokens.

## 10. Useful commands

```bash
# start infra
cd /d/superapp/infra/local && docker compose up -d

# get a token
TOKEN=$(/d/superapp/tools/token.sh)

# decode it
echo "$TOKEN" | cut -d. -f2 | tr '_-' '/+' | base64 -d 2>/dev/null | jq .

# build everything
cd /d/superapp/services && mvn clean install -DskipTests

# place an order (end-to-end through the gateway)
curl -s -X POST http://localhost:8082/orders \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"items":[{"productId":1,"quantity":2}]}' | jq .

# watch kafka
export MSYS_NO_PATHCONV=1
docker exec -it superapp-kafka /opt/kafka/bin/kafka-console-consumer.sh \
  --bootstrap-server localhost:9092 --topic order.placed.v1
```

Startup order matters: **Docker → Keycloak → services → gateway**.
Services read Keycloak's discovery document at boot.
